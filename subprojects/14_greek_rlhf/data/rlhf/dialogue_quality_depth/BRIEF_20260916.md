# Implementation brief — dialogue quality-depth pilot (Phase 0 code, offline)

You are implementing, in THIS directory only, the software for the plan
`../../../docs/RLHF_COORDINATION/DIALOGUE_EXPERIMENT_PLAN_20260916.md` (read it fully first), its config
`../../../docs/RLHF_COORDINATION/DIALOGUE_PILOT_CONFIG_20260916.json`, and the addendum
`../../../docs/RLHF_COORDINATION/DIALOGUE_SAMPLING_QUALITY_DEPTH_20260916.md`. The plan is the specification; where this
brief is more specific, follow the brief. Phase 0 = build and verify with zero inference calls. Fable (me) orchestrates every
later phase by calling your CLI; you never start a provider, a pod, a Sol call or a network request while implementing.

## Hard rules
- Write only inside this directory (`data/rlhf/dialogue_quality_depth/`). Never modify `../prompt_generator/` (frozen release
  0.1 with hash-verified RELEASE.json), `../*.py`, `../../math/`, or anything under `docs/`. Importing/reading them is fine.
- Python 3.11+ standard library only (like the generator). No pip installs, no third-party packages.
- All tests must run offline with fake clients: `python3 -m unittest discover -p 'test_*.py'` from this directory. No test may
  spawn `codex`, open a socket, or read `~/.codex`.
- Separate state: everything runtime lives under `./runtime/` (own SQLite registry + JSONL logs). The generator's registry
  `../prompt_generator/runtime/` may be opened READ-ONLY (sqlite `?mode=ro`) to learn which source instances/families are
  already reserved by its runs so you never reuse them; never write there.
- Idempotent, resumable, append-only: every provider call, Apertus completion and Sol call is appended immutably to
  `runtime/ledger.jsonl` BEFORE the request is sent (reservation) and completed with a second record after; restarts never
  overwrite earlier usage and never let a retry pick a "nicer" completion (an observed completion is final).

## Existing interfaces you must reuse
- Sol client: `../../math/codex_server.py` → `CodexServer()`; `.start()`; `.call(prompt: str, schema: dict, model='gpt-5.6-sol',
  effort='high', timeout=900) -> dict` (JSON validated against the schema); `.close()`. Read the file. Wrap it behind a small
  interface `SolClient` with a fake implementation for tests. Default effort for this pilot: `high`. Every call counts against the
  120-call cap from `budget.max_new_sol_calls` and the phase reservations in `budget.sol_reservations` (count before the
  request, including failed attempts). Refuse to call when the cap or the phase reservation would be exceeded, unless a
  recorded reallocation (`runtime/forecast.json`) moves capacity between phases while keeping the 120 total.
- Apertus inference: an OpenAI-compatible vLLM server (chat completions) reachable at a base URL such as
  `http://127.0.0.1:8000/v1`, served model name given on the CLI. Look at `../sample.py` for the request shape. Frozen sampling for
  raw rollouts AND candidates: `temperature 0.8, top_p 0.95, max_tokens 1500, n=1`, no system prompt, the server applies the
  checkpoint's own chat template. Record for each completion: raw text byte-identical, sha256 of the text, `finish_reason`
  (`length` ⇒ truncated, distinct terminal code), prompt/completion token usage, served model id, wall time. Wrap behind
  `TargetClient` with a fake for tests. Before any real rollout the CLI must fetch `/v1/models` and record the served model id and
  the checkpoint receipt Fable passes on the CLI (`--checkpoint-sha256 54d445bc639b7222ad872b4d8dca5e913dbf4c4d427fbf56183e28361006e763`,
  epoch1 of run R4_full, model `fffoivos/greek-apertus-8b-sft-r4-full`) into `runtime/runtime_config.json`.
- Seeds: source-complete seeds with private constraints/reference answers come from the frozen generator's fixture catalogue
  (`../prompt_generator/fixtures.py` `build(family_id, rng, difficulty, language)` + `validate`, `../prompt_generator/core.py`,
  `design.json`, `sources.py`). Read them to learn the family ids, purposes (everyday / instruction / factual / safety / math),
  language support, difficulty levels, and which fields are PRIVATE (reference answers, checks, instruction_spec). Reserve whole
  source families for this pilot in your own registry; a family reserved by the generator's runs (read-only lookup) or by the smoke
  stage can never appear in the measurement stage; entire-family split assignment (`train` for measurement, a reserved
  `smoke` pseudo-split for the 6 smoke chats). Record `instance_hash`/family/split per trajectory in the manifest.
- Judge style reference (not to be reused as-is): `../judge_rank4.py` and `../prompts/judge_rank4_v2_en.txt` (rubric v2.4: our
  preferences for Greek replies, absolute verdicts reinforce/neutral/discourage, issue tags). The candidate ranking prompt of
  this pilot must embed that rubric text verbatim (read at runtime from that path, sha16 recorded) and add the pilot's own rules
  (3 candidates, randomized letters, hidden original status, ties allowed, acceptability of the chosen answer).

## Components (file names from plan §4; keep them, add what you need)
`schemas.py` (dataclasses + JSON validation for seed, event, trajectory, prefix-local annotation, adjudication, selection,
candidate, preference, receipt), `rollout.py` (one-response-per-turn state machine over depth waves across trajectories,
resumable JSONL event log `runtime/<stage>/user_events.jsonl` + `trajectories.jsonl`, terminal codes: `completed`,
`horizon`, `context_limit`, `truncated_output`, `infra_failure`, `ambiguous_timeout`), `user_policy.txt` (the Sol user-simulator
prompt, in English, conditioning only on the visible prefix + the user's own goal/interaction plan/attitude/register, never on
private references, evaluator labels or future turns; may acknowledge a mistake it can see from the visible task, as an ordinary
user would; emits `done` when the task is genuinely complete; no padding to reach 8 turns), `openings.py` (Sol writes the
opening user message from the seed and interaction plan; several seeds per call; private fields stay private), `annotate.py` +
`turn_quality.txt` (prefix-local packets; batching ≤8 short / ≤4 long packets and ≤24,000 estimated input tokens per call, never
two prefixes of the same trajectory in one call; fields listed in plan §7; severity good/minor/serious/unjudgeable; oracle hooks:
for math/instruction seeds with executable or exact checks, run them in code and pass the result to the annotator as
`verifier_result`), `analyse.py` (first-serious-failure and recovery derivation in code; quality×depth tables; report JSON+HTML),
`select.py` (P/R/C eligibility + deterministic allocation of plan §9 with receipts), `candidates.py` (original + 2 fresh
completions under the byte-identical prefix; prefix sha256), `rank.py` (Sol ranking of the 3), `export_pairs.py`
(`preferences.jsonl`, `rejected_pairs.jsonl`; DPO adapter rows: `{id, prefix_messages, prefix_sha256, chosen, rejected,
chosen_source(original|new), rejected_source, selection_kind(P|R|C), depth, language, task, trajectory_id, receipt}` and an explicit
completion-mask contract written to `ADAPTER_CONTRACT.md`: only the completion tokens are trained, all history tokens masked,
including earlier bad assistant turns; chosen/rejected share the exact prefix), `budget.py` (Sol call ledger + reservations;
GPU ledger fed by Fable: `ledger gpu-start --pod-id --price-usd-hr --eur-per-usd` / `ledger gpu-stop`; admission estimate for sizes
35/28/21/14 from measured smoke rates; conservative wall-time deadline computation; the cap is EUR 5 total, operational stop
EUR 4.00, reserve EUR 1.00), `forecast.py` (Phase 1 forecast: tokens, wall time, throughput, Sol calls per phase; writes
`runtime/forecast.json` with the admitted size; refuses to admit a size whose full annotation cannot be funded within the
remaining Sol reservation), `dqd.py` (single CLI, see below), tests `test_*.py`, `RUNBOOK.md` (exact commands per phase for the
orchestrator, in order, with the gate checks), `ADAPTER_CONTRACT.md`.

## CLI (Fable calls exactly these; keep the names)
```
python3 dqd.py --state runtime init --config <config.json>          # manifest, deterministic axis allocation (seed 9162602), family reservations for smoke + measurement; repairs infeasible joint assignments and exports actual joint counts
python3 dqd.py --state runtime openings <smoke|measurement> [--limit N]
python3 dqd.py --state runtime rollout <smoke|measurement> --endpoint URL --model NAME --checkpoint-sha256 SHA [--max-turns 3|8] [--concurrency 8]
python3 dqd.py --state runtime annotate <stage>
python3 dqd.py --state runtime calibration <stage> [--n 24]          # stratified calibration sample + boundary turns for root review; `adjudicate` ingests a JSONL of decisions
python3 dqd.py --state runtime adjudicate <stage> --decisions FILE
python3 dqd.py --state runtime report <stage>                         # freezes quality_depth_report.json/html (sha recorded); selection refuses to run before the report is frozen
python3 dqd.py --state runtime select measurement
python3 dqd.py --state runtime candidates measurement --endpoint URL --model NAME --checkpoint-sha256 SHA
python3 dqd.py --state runtime rank measurement
python3 dqd.py --state runtime export measurement
python3 dqd.py --state runtime forecast smoke [--admit N]             # writes runtime/forecast.json; admission before measurement outcomes are observed
python3 dqd.py --state runtime ledger [gpu-start|gpu-stop|show]
python3 dqd.py --state runtime status
```
Every command prints a one-line machine-readable summary at the end (`DQD_OK <command> <key=value ...>` or `DQD_FAIL ...`) and
exits non-zero on failure. The smoke stage uses `max_assistant_turns 3`, measurement `8` (explicit override of the generator's
older default of 4, recorded in the manifest as required by the plan).

## Required tests (plan §4, all with fake clients)
raw sampling n=1 despite any per-slice default; byte-identical stored assistant text and sha; the user simulator prompt contains
only the prefix (assert no private field, no annotation, no future turn leaks into the prompt string); the annotator packet never
contains a later turn; first-serious-error and recovery indexing; "no failure observed" is a valid outcome; natural completion vs
truncation vs horizon vs context-limit terminal codes; idempotent restart after a crash mid-wave without re-sampling an already
observed completion; shared-prefix hashes equal between original and new candidates; export masks all history; a family never
appears in two splits/stages; quota counters count accepted trajectories only; atomic Sol call reservation (cap and phase
reservation refused when exceeded, failed attempts counted); deadline shutdown signal from budget; annotation batching limits
(packet counts, token estimate, no overlapping same-trajectory packets); selection allocation rules with largest remainders and
per-trajectory caps; ranking with randomized letters mapped back and original status hidden; export refuses ties/all-bad and
records them in rejected_pairs.jsonl.
