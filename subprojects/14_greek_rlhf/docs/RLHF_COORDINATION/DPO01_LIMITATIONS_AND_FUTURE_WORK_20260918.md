Purpose: preserve what we deliberately do not know, without spending more LLM calls or delaying the first pilot.
Status: registered before training. Update evidence/status after the run; do not erase initial concerns.

## Updating this register
For each resolved or newly material issue append: date, evidence path/hash, observed result, whether it changes the pilot conclusion, and recommended future action. Leave “unmeasured” where no check was run. Never turn a deferred item into a claimed pass.

Prioritization after the pilot:
1. If numerical/masking failure: repair that exact failure, not the data pipeline.
2. If IF improves but retained capabilities regress: inspect affected saved outputs and update magnitude before expanding data.
3. If no detectable behavioural change despite correct training: assess update strength and statistical power before buying annotation.
4. If the pilot is promising: address missing dialogue and independent behavioural evaluation before claiming all-around improvement.
