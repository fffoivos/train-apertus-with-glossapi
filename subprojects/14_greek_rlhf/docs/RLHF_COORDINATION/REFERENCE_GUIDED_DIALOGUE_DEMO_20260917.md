## Common protocol

- Every assistant reply is generated by the pinned adapted Apertus checkpoint (current reviewed identity G4F6P1; verify exact checkpoint before execution). Sol must not impersonate Apertus.
- One unselected assistant reply per turn. Maximum six assistant replies per conversation; natural completion or abandonment may end earlier.
- No scripted requirement for model failure, correction, dissatisfaction or reaching the horizon.
- Adaptive simulated user: may clarify, provide an example, decompose, simplify, express frustration, accept progress or leave, according to the user's plausible knowledge and patience.
- The initial preference/knowledge state persists. Do not invent dissatisfaction with a requirement the answer already satisfied.
- A previously unstated preference can be revealed as a new preference; do not judge the earlier assistant as having violated a hidden instruction.
- Keep public conversation, private user state and evaluator-only reference as separate input views.
- Record each user strategy and what new information it provides.
- Keep original assistant text unchanged and retain observed trajectory history.
- Respect the verified context window; plan reasonable completion allowances per task. Record context cutoff separately from task failure and never silently trim history.
- Mark possible future branching points before first serious error, after helpful intervention and during healthy continuation. Do not generate alternative replies in this initial demo.

## Six concrete cases

### RGD001 — Greek email revision

Opening: “Γράψε ένα σύντομο μήνυμα στον υπεύθυνο του σεμιναρίου: δεν μπορώ να παρευρεθώ την Παρασκευή και θέλω να ρωτήσω αν μπορώ να συμμετάσχω στην επόμενη συνάντηση. Δεν θέλω να εξηγήσω προσωπικούς λόγους.”

Private user preferences: courteous and moderately formal; about 50–80 words; neither ceremonious nor familiar; a direct request. Ordinary patience, can point to an unwanted phrase.

Reference draft, visible to user simulator/evaluator but not Apertus:
“Καλησπέρα σας, δυστυχώς δεν θα μπορέσω να παρευρεθώ στο σεμινάριο της Παρασκευής. Θα ήθελα να ρωτήσω αν υπάρχει δυνατότητα να συμμετάσχω στην επόμενη συνάντηση και αν χρειάζεται κάποια ενέργεια από την πλευρά μου. Σας ευχαριστώ για την κατανόηση και παραμένω στη διάθεσή σας για την επιβεβαίωση της αλλαγής.”

Reference is illustrative, not an exact-match answer. The word range is an approximate private preference, not a hidden hard constraint for grading the first answer. If Apertus already produces a satisfactory message, the user may finish. If not, the user should identify a concrete style/length issue, possibly supply a short phrase, and preserve the facts.

### RGD002 — English short article revision

Opening: “Write a short article for our neighbourhood newsletter inviting people to a seed-swap afternoon. It is on 12 October, 3–5 pm, at the community garden. Entry is free, and people can come even if they have no seeds to bring.”

Private target: roughly 100–140 words, friendly factual prose, no advertising hype. Reader should know when/where, that attendance is free, and that bringing seeds is optional. User can give an example of the tone they want.

Reference includes all supplied facts and a restrained invitation. It must not add promises of refreshments, experts, equipment or accessible facilities. Opus may supply a concrete reference draft before rollout, keeping factual checks separate from the prose.

Possible helpful response only if warranted: point to an exaggerated sentence and offer a plain replacement. Healthy continuation could ask for a short title or a shorter version; stop if there is no real remaining need.

### RGD003 — Greek printer troubleshooting

Opening: “Μετά την αλλαγή του Wi-Fi, ο φορητός μου δεν βρίσκει τον εκτυπωτή. Και οι δύο φαίνεται να έχουν ίντερνετ. Τι να ελέγξω;”

Evaluator-only world:
- Laptop is on Home; printer is on isolated Home-Guest.
- Printer is powered on and prints a local test page.
- Printing previously worked; no hardware fault is injected.
- Same main-network connection permits a successful print in this simulated setup.
- A supported USB connection is also a valid temporary workaround if the user has the cable.

User-visible initial state: the opening symptom; nonexpert; willing to perform simple checks. A printed network-status page reveals Home-Guest; laptop network settings reveal Home. User does not initially know the diagnosis.

World response rules:
- Restart alone does not change network membership.
- Local printer test succeeds.
- Report/check of network names returns the fixed names.
- Joining the printer to Home resolves discoverability in this defined setup.
- Unknown device-specific menu paths or unsupported actions are not automatically declared successful.

Keep root cause out of the user-simulator view; an observation resolver reveals only what the user's plausible action checks. Unknown actions require adjudication/explicit uncertainty, not invented outcomes.

### RGD004 — English Python environment troubleshooting

Opening: “My script says ‘ModuleNotFoundError: No module named requests’, but I already installed requests. I’m running it in VS Code. What should I check?”

Evaluator-only world:
- VS Code runs /project/.venv/bin/python.
- The user installed requests into a different global interpreter.
- The virtual environment lacks requests.
- No unrelated network or permissions failure is injected.
- Checking the active interpreter and package location reveals the mismatch.
- Installing into the active virtual environment resolves the import. Selecting the intended environment with the package may be valid if compatible with the project.

Private user state: beginner who can copy a command and report its output; does not understand interpreter environments. Repeated package installation using the same wrong interpreter produces the same outcome.

Define exact outputs for supported checks before rollout. Never claim an actual installation or real machine action occurred: the transcript is a simulated scenario.

### RGD005 — Greek learning about division by fractions

Opening: “Ξέρω τον κανόνα «αντιστρέφω και πολλαπλασιάζω», αλλά δεν καταλαβαίνω γιατί όταν διαιρώ με ένα κλάσμα μπορεί να βγει μεγαλύτερος αριθμός.”

Learner view:
- Understands halves/quarters as quantities.
- Can multiply simple fractions mechanically.
- Misconception: division necessarily makes a quantity smaller.
- Wants an explanation, not just the rule.
- Can attempt a small example but should not automatically infer every consequence from one explanation.

Evaluator-only reference:
- Division can count how many groups of divisor size fit in a dividend.
- Three-quarters of a cup contains 1.5 half-cup portions.
- Transfer check: two-thirds divided by one-third equals two.
- Check whether the learner applies the grouping interpretation, not just repeats a supplied sentence.

Do not provide the learner simulator with gold answers to the transfer question. Track plausible knowledge-state updates from what Apertus actually explains. Evaluator checks both the explanation and the learner's attempt; simulator claims of “I understand” do not count as verified learning.

### RGD006 — Greek learning about summary versus paraphrase

Opening: “Όταν μου ζητούν περίληψη, συνήθως αλλάζω τις λέξεις κάθε πρότασης και πάλι βγαίνει σχεδόν το ίδιο μήκος. Τι κάνω λάθος;”

Supplied short source, available if the assistant asks for an example or the learner offers one:
“Η δημοτική βιβλιοθήκη παρατείνει το ωράριό της για δύο εβδομάδες πριν από τις εξετάσεις. Θα κλείνει στις εννέα το βράδυ αντί στις έξι. Η αλλαγή έγινε μετά από αιτήματα μαθητών και φοιτητών. Η αίθουσα μελέτης θα παραμένει ανοιχτή, αλλά ο δανεισμός βιβλίων θα σταματά στις έξι.”

Learner state: confuses paraphrasing every sentence with selecting central information; can rewrite sentences but has difficulty deciding what to omit.

Evaluator reference:
- Summarising selects/compresses central information according to purpose.
- A summary should preserve temporary extended study access and, when relevant to the requested audience, the earlier lending cutoff.
- Several summaries are valid; no exact wording target.
- A supported practice sequence uses one attempt, specific feedback and a revised attempt or short transfer text.
- Do not let the learner suddenly produce an expert summary based on a hidden model answer.

## Reference access contract

Three separate views:
1. Apertus: public conversation only.
2. User simulator: goal, preferences/knowledge, patience, visible conversation and observations already legitimately revealed.
3. Evaluator/world resolver: verified solution/world facts and checks. Reveals observations or evaluates progress, never supplies a hidden answer to the learner as if they discovered it.

Writing reference drafts may be in the user's view because those express their own intended style. For troubleshooting, hide the diagnosis; for learning, hide gold transfer answers. These are intentionally different access policies, not one universal reference-injection prompt.

## Review deliverable

One review page or report showing for each case:
- Initial scenario and private reference, labelled clearly.
- Full Apertus/user transcript.
- User strategy changes and newly supplied information.
- Whether the user reaction follows the observed response.
- Whether the world or learning state stays consistent.
- Whether hidden reference information leaked.
- Task result, natural ending/abandonment or technical cutoff.
- Possible prevention/recovery/healthy-continuation sampling points.

Report failures of the user/world simulator separately from failures of Apertus. Review all six conversations before scaling. No forced preference pairs and no automatic admission to training.
