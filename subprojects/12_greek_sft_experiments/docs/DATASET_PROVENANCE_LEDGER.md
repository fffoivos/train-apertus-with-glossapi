## Boundaries discovered on 14-15 Sept
- The maths validator verified derivations against the source reference; wrong references (GSM8K label noise) passed and correct solutions were repaired into agreement in 44 problems. Replaced by the blind-solve rule.
- JSON-escape corruption in Sol outputs (control characters for LaTeX escapes) passed every judge; repaired and audited (plan §9f).
- "Accept" labels from external human review (sl45sms) did not filter the defect classes we measure (docs/reviews/DATASET_REVIEW_sl45sms_20260914.md).

## Trainer masking defect (found 15 Sept 06:10)
`cluster/sft_train.py` validates rows with a flag-aware tokenizer (`tokenize_messages`, per-message `train:false` -> label -100) but trains by handing raw messages to TRL's SFTTrainer with `assistant_only_loss=True`; TRL renders with the patched template whose generation markers cover every assistant turn. So masked turns were supervised in every run that contained them: round 3 (1-G3F2P1: correcting v1 ×2 = 1,130 rows of planted failures and their recoveries; convskills S4 context turns) and the round-three pass variants. The incumbent 1-G2F1P1 and the pilots contained no masked rows. For 1-G4F6P1 the pass excludes every row with a masked turn (correcting v2 dropped whole, S4 rows dropped, format demonstrations declared supervised). Fix for the next run: give TRL the pre-tokenized dataset (`input_ids` + `assistant_masks` from `tokenize_messages`) and verify with a short real run that masked positions stay -100 after packing; until then, no dataset that relies on masking is trained.
Trainer fix prepared (not used for 1-G4F6P1): `cluster/sft_train_maskfix.py`, opt-in with `pretokenized_masks: true` in the config; `_dataset` returns `input_ids` + `assistant_masks` from `tokenize_messages`. Verification plan: a 20-step real run on one node with a correcting-v2 row and a format row, dumping the collator's labels at the masked positions (must be -100) and the packed sequence boundaries; only then may mask-dependent blocks return to a mix.
Note (15 Sept 06:10): `data/convskills/v2/final/rows_final.jsonl` carries 9 duplicated ids (9 extra rows, all S2_*); the assembler deduplicates by id within a block (first occurrence kept, counted as duplicate_id). Round 3 consumed the earlier version of the suite; check its receipt for the same duplication before comparing block sizes.

## 15 Sept 10:40 — reference check: comparator and record identity (astra gate-2 v5)
- Comparator (`data/math/cut2/labelcheck_lib.py`): a pure number on both sides is decided by exact Decimal equality only (no tolerance, no float); anything else by `equiv500`. Re-finalizing with it left the agreed/disagree sets identical (delta 0/0); the four numeric-only agreements (gsm_124, gsm_2836, gsm_3375, gsm_4112) are exact matches.
- Record identity: new solve records store `pfp = sha256(problem_en)[:16]`; the finalizer treats a record as stale when its fingerprint or reference differs from the current manifest and as unsolved when it has no fingerprint. The 12,028 records of the 15 Sept 01:34–03:55 solve were fingerprinted afterwards (`backfill_solve_fingerprints.py`): every manifest source file was last modified before the solve file was created and none since (sha256 + mtimes in `data/math/cut2/out/independent_solve.manifest.json`); the records carry `pfp_backfilled: true`. Bound: this is file-time evidence, not a solve-time record.
- One manifest constructor (`build_manifest`) is shared by the solver and the finalizer; Level-5 references are the boxed answer of the English solution in both.
- Assembly binds the approval file at load and fails if it changes; canonical English references come only from approved records; conflicting approved references reject the problem (0 such problems).
- Exclusions (`data/exclude_rows_r4.json` + reasons, fingerprinted, listed per block in the receipt): c2_gsm_2544 + gsm_2544, c2_math_2094 + math_2094, math_train_4407, math_train_2954, GSM problem 353716 (rows 353716/1916727/2184703, under-specified), convskills_v2:S3c_00357; OpenBookQA "in an ecosystem" removed from the format-block pool.
