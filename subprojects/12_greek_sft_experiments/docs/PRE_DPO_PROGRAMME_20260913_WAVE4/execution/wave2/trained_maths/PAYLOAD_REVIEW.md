# Sol audit payload provenance and authorization evidence

The owner explicitly requested Sol parallel work and instructed us to start the audit plan, then made completion of the evolving SFT improvement plan the active goal. That plan names this before/after audit of 120 trained Greek maths examples. Destination is the same OpenAI Codex Sol service used in the preceding authorised maths audit and in the source generation/correction workflow.

This frozen payload contains 30 public GSM8K training problems, 40 public MATH training problems, and 52 synthetic educational maths scenarios from this project's Sol generation (including two known-failure controls). Original English text for all 70 translated examples was matched exactly to the source corpus cache; counts and file hashes are in payload_provenance_review.json. Before/after Greek targets are the corresponding Sol adaptation/correction outputs, not private user conversations. Native IDs match the recorded synthetic generator output. The payload contains no credentials, private-key blocks or email addresses in the checked fields. It includes source IDs, mathematical text, generated targets and audit metadata. No unrelated files or private communications are sent.

The audit writes findings only. It does not publish a dataset, send messages to people, alter completed data or allocate CSCS resources. The exact batch cap is 140 calls including retries, 61 primary calls for 122 full records, with a four-call probe before ramp-up. A retry of the approval request should use this exact reviewed payload and destination; the earlier rejection must not be bypassed through another execution route.
