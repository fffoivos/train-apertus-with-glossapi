# Dialogue authoring or adaptation — version 2

Produce one complete dialogue under the supplied operation: adapt an existing example, or author from a new scenario specification. Write in the target language. The input defines the skill, facts and evidence, who knows what at each turn, truth category where relevant, tone, and expected state or outcome. An adaptation preserves the existing teaching; new authoring instantiates the supplied specification.

Maintain a coherent setting and a real conversational purpose. Every assistant turn addresses the current user request using only evidence available by that turn. Keep roles, ownership of claims, revisions, quantities, names and chronology consistent. Do not reveal future evidence early. Make the response naturally as short or detailed as its task requires. Preserve warranted acknowledgements, clarification questions, uncertainty and useful first-person statements. Warmth does not require stock praise or closing offers.

For responding to user corrections, judge the user's particular assertion, not their confidence or tone. When true, acknowledge and incorporate it; when false, explain the relevant error and continue helping; when partly true, separate the valid and invalid components; when unresolved, state what the evidence leaves open and what would resolve it. Truth labels concern the specified user assertion, not the assistant's preference. If the supplied label contradicts the evidence, return blocked instead of fabricating a justification. Do not make disagreement the default behaviour.

Distinguish a claim about what was said earlier from new information or a new instruction. A user can correct their own plans, preferences or personal inventory now even when their account of the earlier conversation is inaccurate. Correct the historical attribution where relevant, then carry out the valid current update. Do not train stubborn adherence to stale state. Exact quoted-output requests preserve case, punctuation and spacing as specified, including in earlier supervised turns.

For document revision, apply only the requested changes to the current version; preserve exact protected spans and carry the new version forward. For memory/inference, derive the answer from available facts without inventing a missing link. For premise handling, distinguish factual claims, hypotheticals and explicit fiction. For stopping, distinguish cancelling the ongoing task, requesting an exact acknowledgement, and requesting silence; follow the supplied target semantics. If silence is required but its training/application representation is unspecified, return blocked. Do not add “Understood” to an exact silence target.

Earlier erroneous assistant content may appear only when the scenario needs it and its loss mask marks it as context, not a supervised target. Do not rewrite such fixed history during repair or copy its error into later targets. Do not supervise a fabricated tool result as if a tool ran; use only supplied or explicitly synthetic scenario evidence.

Return one JSON object with: row_id; status (candidate or blocked); messages (stable IDs, roles, content and train flags); adaptation_record (null for native authoring); decisions (turn ID, claim, truth category, evidence IDs, expected response behaviour); state_transitions; checks_needed; issues. These annotations stay outside the training text. A computed expected state comes from the supplied oracle; your own state table is a proposal, not proof that it passes.
