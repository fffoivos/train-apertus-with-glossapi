## 3. Dialogue: the diagnosis and the fixes

What the runs showed (mixed profile, same simulator; arm B's R1 as the baseline): R3 is better on redirects (stale 67 vs 74%), request honouring (60 vs 45%), coherence (86 vs 79%) and tone (89 vs 76% fine); worse on tail copying (9.2 vs 5.8%), stop instructions (90 vs 100%) and premise / false-claim handling (0.78 vs 1.23 on the false_claim turns). The interviews add: concessions to false challenges followed by self-contradiction («Σωστά, το διορθώνω» then the correct content anyway), and constraint loss during rewrites.

Root causes with evidence: (H10) the correcting set holds against a false correction in 20 of 3,692 turns and accepts corrections in 272; the model learned the acknowledgement, not the distinction; the pass WITH the correcting set keeps false-claim handling at 0.86 while the exact historical pass restores 1.33. (H8, demoted) the English chat imports' register contributes but is not the mechanism. Loops start after a wrong step (11 of 12 inspected) and are a termination failure, not a data artefact.

Fixes, each with the QA it needs:
1. **Correcting set v2**: at least one third FALSE and one sixth PARTLY-true corrections, claim_truth known for every one, the hold/accept target checked by a second reader against claim_truth (not a filter, a measured error rate); absurd-premise and impossible-self turns added with the identity contract as target; report the true/false/partial counts as an acceptance check. Pilot 100 dialogues → astra review → scale 600.
2. **Version editing and inference memory** (MultiChallenge's two lowest axes): a new lane in the suite generator: multi-turn tasks where turn N asks for an edit of turn N−2's answer and the check is "everything not mentioned is unchanged" (diff-based, programmatic), and tasks where a fact from turn 1 must be used at turn 4 without being repeated (check: the fact appears; the model does not ask for it). Pilot 200 → checks → review → scale 2,000.
3. **Stops and tail copies**: the suite's persistent-instruction and stop lanes exist; their share in the pass should rise; measure after R4 before building more.
4. **Loops**: decoding intervention at serving (repetition penalty 1.05) and, in DPO, on-policy pairs where the rejected sample is the loop; not an SFT data item.
5. **Interviews**: the frozen-follow-up mode (§1) before the next comparison.

## 4. The Greek math set: what I am NOT sure of, and the workflow that would settle it

The claim: the set's target style (42-word quick solves ending in an answer line) is what R3 copied (35-word unboxed answers, 343 of 500) and it is worse than the English block's style (worked reasoning, boxed), which stage 1 carries into Greek at 12.8%. The gap to Krikri on MGSM-el (0.68 vs 0.52) is the reason the set exists at all.

Dimensions where the current prompt and workflow are unproven, and the check for each:

| dimension | uncertainty | check before scaling |
|---|---|---|
| target style transfers | the whole hypothesis; only an A/B settles it | pilot 300 rows, trained as a slice inside a Greek pass on R3 vs the same pass without it (2 × 1.5 nh + light evals); read MATH-500-el, MGSM-el and answer length |
| step correctness beyond the final answer | the reference answer verifies the end, not the derivation; Sol can reach a right answer through a wrong step | astra/Opus step audit of 60 rows per pilot as a measured error rate (not a filter); if > 5% wrong steps, change the prompt, not the rows |
| length and structure match the English block | I guessed 100–250 words; OpenMathInstruct's actual distribution should be the target | measure OpenMathInstruct solution lengths per problem type and set the prompt to that band; acceptance = median within ±25% |
| Greek quality | Sol's Greek needs the guarded polish pass (owner rule) | polish pass with guards; sample read by the owner |
| coverage | Level 5 absent; subjects uneven | quotas per level and subject in the build; Level 5 from the 1,500 candidates |
| decontamination | MATH-500 test and MGSM test are held out; train splits are used | 8-gram check against both, as in G3 |
| scorer compatibility | decimal comma and Greek units inside \boxed break extraction | targets end with \boxed{} in the reference's form; equiv500 on a sample of targets must reach 100% |
| reasoning register | «σκέψη βήμα-βήμα» in Greek may differ from English CoT in ways that matter | read 30 rows blind against 30 English ones (owner or astra) |

Workflow: pilot 300 (Sol, one call per row) → acceptance checks (length band, boxed, equiv500 = 100%, levels) → astra review of 60 + step audit → prompt fixed → scale (11,500) → polish pass → assembly gates → the A/B pass read-out decides whether it goes into R4's main mix.

## 5. The QA workflow for every generated set (answer to "maybe add other QAs")

pilot (100–300) → programmatic acceptance checks written before the pilot → astra review of a sample with a disposition table → prompt/policy fixed → scale → guarded Greek polish → assembly gates (receipt, masking, decontamination, dedupe) → an A/B training read-out on the benchmark the set targets, before the set enters a main mix. Judge labels never filter silently; every filter reports what it removed by difficulty.
